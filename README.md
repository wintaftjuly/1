# 여운 — 캐릭터 아카이브

서버나 외부 라이브러리 없이 실행하는 정적 사이트 시안입니다. 첨부된 파일철 레퍼런스를 바탕으로 종이 질감, 세로 식별 라벨, 연도별 폴더 탭과 마운트된 초상 카드를 사용합니다. 각 연도는 한 화면 이상을 차지하며 최신순으로 이어집니다. 최초에는 가상 캐릭터와 로컬 일러스트를 표시합니다. 실제 캐릭터 자료는 포함되어 있지 않습니다.

## 실행

```sh
cd /workspace/1
python3 -m http.server 8000 --bind 0.0.0.0
```

HTTP로 실행하세요. 별도 설치·빌드·API 키가 필요하지 않습니다.

## 관리와 공유

아카이브 관리에서 사진, 이름, 커뮤니티, 활동 연도를 등록·수정·삭제합니다. 최신 연도부터 묶어 표시합니다. 사진은 최대 5MB이며 저장 전에 최대 1000px WebP로 변환합니다. 편집은 **해당 브라우저의 localStorage에만 저장**됩니다. 브라우저 데이터 삭제, 저장 용량 제한에 대비해 `자료 내보내기`로 백업하세요. 데이터 파일에도 사진이 포함됩니다.

방문자에게 공개하려면 내보낸 `archive.json`을 `index.html`과 같은 폴더에 넣고 정적 호스팅에 다시 업로드합니다. 방문자의 로컬 편집은 공개 원본을 바꾸지 않습니다. 로컬 편집 기록이 있으면 공개 데이터보다 우선합니다. 새 공개 자료를 확인하려면 다른 브라우저 프로필을 사용하거나 백업한 뒤 사이트 저장 데이터를 삭제하세요.

GitHub는 필수가 아닙니다. Cloudflare Pages 등의 직접 업로드를 사용할 수 있고, GitHub Pages를 쓰면 GitHub 저장소가 필요합니다. 무료 요금제도 용량·사용량·정책 제한이 있으므로 무제한 무료는 보장하지 않습니다. 이 구현에는 관리 서버, 로그인, 데이터베이스가 없습니다. 어느 기기에서나 로그인해서 즉시 공개 자료를 수정하려면 인증된 CMS 등 별도 관리 구조가 필요합니다.

## 보안·배포

외부 스크립트, 폰트, 분석 도구, 이미지 요청을 사용하지 않습니다. 사용자 문자열은 textContent로 출력하고, 가져오기 이미지는 지정된 로컬 샘플이나 PNG/JPEG/WebP 데이터만 허용합니다. 가져온 SVG·외부 이미지 URL은 거부합니다. HTTPS 정적 호스팅을 사용하고, 공개하지 않을 개인정보·비밀키를 자료에 넣지 마세요. 모든 취약점의 부재를 보장하지는 않습니다.

`_headers`는 Cloudflare Pages 등 지원하는 호스팅에서 CSP와 보안 헤더를 설정합니다. 다른 호스팅은 해당 서비스의 헤더 설정을 확인하세요. 관리자 편집 내용은 공개 서버에 전송되지 않습니다.

큰 연도 그룹은 잘리지 않도록 한 화면보다 길어질 수 있습니다. 스크롤 스냅은 proximity로 설정하며 작은 화면·동작 감소 설정에서도 콘텐츠를 읽을 수 있습니다.

## 제목과 문구 편집

상단 `문구 편집`을 누른 뒤 점선 문구를 클릭해 입력합니다. `모든 문구`에서는 사이트 이름, 큰 제목의 앞·뒷부분, 안내문, 세로 라벨, 하단 문장, 캐릭터 수 단위와 hover 문구까지 수정할 수 있습니다. `저장`은 현재 브라우저에만 보관하고 `취소`는 편집 시작 시점으로 되돌립니다. 사진 배치와 hover 모션은 그대로 유지됩니다.

모든 방문자에게 반영하는 방법:

1. `문구 편집 → 공개용 문구 내보내기`로 `settings.json`을 다운로드합니다. 이것은 사이트 자체가 브라우저에서 생성하는 다운로드입니다.
2. GitHub 저장소 `https://github.com/wintaftjuly/1`에서 `Add file → Upload files`를 누르고 파일을 올려 기존 `settings.json`을 교체합니다.
3. `main`에 커밋하면 GitHub Pages가 다시 배포합니다. 배포 완료 뒤 새로고침하세요.

설정은 `settings.json`에서 읽습니다. 로컬에 저장한 문구가 공개 문구보다 우선합니다. 새 공개 문구를 확인하려면 시크릿 창을 사용하거나 `문구 편집 → 모든 문구 → 기본 문구로 되돌리기 → 저장`을 선택하세요. 다른 방문자는 관리자 계정 없이 공개 원본을 바꿀 수 없습니다. 본인도 사이트 화면만으로 서버에 직접 게시할 수는 없습니다.

문구 파일은 50KB, 각 문구는 600자 이하입니다. 문자열은 HTML로 실행하지 않고 텍스트로 표시합니다. 사진 내보내기와 문구 내보내기는 서로 다른 파일입니다. 문구를 바꿀 때 캐릭터 자료는 유지됩니다.

## 현재 시각 방향

첨부된 색상 레퍼런스의 초록 `#3CA081`, 적갈색 `#B1302B`, 크림 `#F5DEAF`를 적용했습니다. 가독성을 위해 어두운 갈색을 보조색으로 사용합니다. 로컬 SVG 커서는 픽셀 화살표·선택 도구 모티프이며, 작은 컬러 스와치와 선택 테두리 장식은 1990년대 말 그래픽 편집기를 참고했습니다. 터치 기기에는 커서를 표시하지 않습니다.

## 비공개 저장소 + Cloudflare Pages

GitHub Pages를 바로 중단하거나 저장소를 먼저 비공개로 바꾸지 마세요. 다음 순서로 옮깁니다.

1. `https://dash.cloudflare.com/sign-up`에서 무료 Cloudflare 계정을 만듭니다.
2. 대시보드의 `Workers & Pages`에서 Pages 프로젝트를 만들고 GitHub 저장소를 연결합니다. GitHub 연결 승인 시 `wintaftjuly/1` 저장소만 선택해도 됩니다. 도메인 구매나 DNS 변경 없이 `pages.dev` 주소를 쓸 수 있습니다.
3. 저장소 `wintaftjuly/1`, 운영 브랜치 `main`, 프레임워크 `None`, 빌드 명령 `node scripts/build.mjs`, 출력 디렉터리 `dist`로 설정합니다. 루트 디렉터리는 비워 두고 배포합니다.
4. 생성된 `https://<프로젝트명>.pages.dev/`에서 연도 그룹, 사진, 문구 편집과 관리 기능을 확인합니다. Pages 사이트는 공개이고, 현재 편집은 여전히 방문자 브라우저에만 저장됩니다.
5. 새 주소가 정상적으로 열린 다음 GitHub 저장소 `Settings → General → Danger Zone → Change repository visibility → Make private`를 선택합니다. 저장소 비공개 전환으로 기존 GitHub Pages 주소는 플랜에 따라 사용할 수 없게 될 수 있습니다.
6. 비공개 전환 후에도 Cloudflare GitHub 앱이 저장소에 접근할 수 있는지 확인하고 새 배포가 성공하는지 검증합니다. 이후 수정은 비공개 저장소에 올리면 Pages가 재배포합니다.

빌드는 스타일·실행 코드·샘플 초상·커서·초기 데이터를 포함한 단일 `index.html`을 생성하고, 필요한 공개 데이터 파일만 `dist/`에 복사합니다. README, 빌드 스크립트, Git 기록은 배포하지 않습니다. `node scripts/build.mjs`는 반복 실행할 수 있으며 의존성 설치가 필요 없습니다. Cloudflare의 현재 무료 요금 한도와 가입 화면을 확인하세요. 유료 기능이나 도메인 구매는 이 정적 사이트에 필요하지 않습니다.

이전 도메인과 새 도메인의 localStorage는 공유되지 않습니다. 캐릭터와 문구를 기존 사이트에서 로컬 편집했다면 각각 `archive.json`, `settings.json`으로 내보내 백업하고 새 사이트에서 가져오세요. 공개 원본에도 반영하려면 GitHub의 해당 파일을 교체해야 합니다.

저장소를 비공개로 해도 웹사이트가 브라우저에 전달하는 HTML, CSS, JavaScript, 이미지와 공개 JSON은 열람 가능합니다. 파일 압축은 접근 제어가 아닙니다. 이미 공개된 기록이나 복사본을 비공개 전환으로 회수할 수는 없습니다.

## 배포 파일 로딩 실패 대응

GitHub Pages의 루트 `index.html`은 생성된 독립 실행 페이지입니다. 별도 CSS·JavaScript·샘플 이미지 요청이 실패해도 기본 화면과 편집 기능이 실행됩니다. `settings.json`과 `archive.json`이 읽히면 최신 공개 자료를 사용하고, 읽지 못하면 마지막 빌드에 포함된 자료를 표시합니다.

HTML 수정은 `src/index.html`, 스타일은 `style.css`, 동작은 `app.js`에서 하고 `node scripts/build.mjs`를 실행하세요. 생성된 `index.html`, `_headers`도 함께 커밋해야 GitHub Pages에 반영됩니다. Cloudflare Pages 빌드는 이 명령으로 최신 결과를 생성합니다. `_headers`에는 인라인 코드의 정확한 SHA-256을 허용하는 CSP를 생성하며 `unsafe-inline`을 허용하지 않습니다. 저장소나 사이트를 비공개로 바꾸는 작업은 아직 수행하지 않았습니다.
